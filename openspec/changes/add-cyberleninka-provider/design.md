## Context

Мотивация — в proposal.md. Текущее состояние Papeer:

- `search.Provider` (`internal/search/provider.go:6`) и `RawPaper`
  (`provider.go:12`) — формат уже зафиксирован; образец реализации —
  `internal/search/openalex.go` (конструктор с `baseURL` test hook, DTO,
  маппинг, `DoJSONWithRetry`).
- `internal/httpclient.Client` уже умеет: per-host заголовки/rate-limit
  (`SetHostHeader`/`SetHostRateLimit`, `client.go:66,81`), JSON POST
  (`PostJSON`, `client.go:234` — принимает `extraHeaders`, которыми можно
  перекрыть UA `UAFirefox` на вежливый `PoliteUA(email)`), скачивание файлов
  (`DownloadFile`, `client.go:268` — 3 попытки с UA-ротацией, Referer только
  как `https://<host>/` на 2-3 попытках).
- Загрузка: `download.Engine` проходит по `DefaultSourceOrder`
  (`resolver.go:37`), каждый источник резолвит URL, затем `FetchPDF`
  (`fetcher.go:144`) качает и валидирует (`%PDF-` + размер,
  `validator.go`). Источник `search_report` уже пробрасывает пред-найденный
  `info.PdfURL` без проверки хоста и стоит первым в цепочке.
- Регистрация: списки провайдеров `SearchAxis`/`SearchAllAxes` в
  `internal/app/app.go` (~строки 663–667, 972–976), пробы
  `CheckSearchProviders` (~414), источники в `buildDownloadSources`
  (~870–876). Per-host лимиты выставляются там же, у `makeHTTPClient`
  (пример — `api.semanticscholar.org` на 910–915).
- Референс (боевые Python-скрипты, формат API подтверждён):
  `harvest_cyberleninka.py` (POST `/api/search`, пагинация, `strip_tags`) и
  `fetch_ru_refs.py` (ретраи 3/8/20 c, Referer на страницу статьи, `%PDF-`
  + 50 КБ).

## Goals / Non-Goals

**Goals:**
- Провайдер поиска как самостоятельный файл-близнец `openalex.go`; логика
  существующих провайдеров не меняется.
- Языковой скоуп оси: дефолт «только англоязычные источники», флаг —
  «только русскоязычные», с расширяемым набором RU-источников. Расширяемость
  обеспечивается одним аддитивным методом `Language()` в интерфейсе
  `search.Provider` — провайдеры объявляют язык сами, без центрального реестра
  (существующие провайдеры получают тривиальный `Language() = "en"`).
- Минимум изменений в `httpclient`/`fetcher`: только то, что необходимо для
  Referer при скачивании.
- Источник скачивания использует пред-найденный `PdfURL` и не делает
  сетевых вызовов.

**Non-Goals:**
- Разбор пагинации/глубокий харвест: один запрос на поиск (как остальные
  провайдеры Papeer берут одну страницу), а не постраничный обход до 100.
- Локализация имён провайдеров: в UI (`SettingsView.vue:279`,
  `SearchLogDrawer.vue`) имена выводятся как есть — i18n-ключи не нужны,
  задача отмечена как опциональная в DoD задачи.
- Не трогаем существующий `search_report`: он остаётся первым, так как
  является источником по умолчанию для всех провайдеров.
- Третий скоуп «all» (англ.+рус. вместе): не вводим, пока не потребуется; тип
  колонки TEXT позволяет добавить значение без миграции структуры.

## Decisions

### 1. Поиск через существующий `PostJSON` + перекрытие UA

`PostJSON(ctx, url, body, extraHeaders)` уже есть и умеет применять
per-host заголовки; `extraHeaders` перекрывают дефолтный `UAFirefox`.
Передаём `{"User-Agent": PoliteUA(client.email)}` — вежливый UA с mailto,
как в референсе. Ретраи 429/502/503/504 (3 попытки, бэкофф 3/8/20 c)
реализуем в провайдере (аналог `fetch_ru_refs.py`), т.к. `PostJSON` не
имеет retry-варианта, а circuit breaker движка срабатывает на уровне
исполнителя. Парсим сырой байтовый ответ через `json.Unmarshal`.

Альтернативы: новый `DoJSONPost` в httpclient — отклонено, `PostJSON`
подходит без доработок.

### 2. Один запрос на поиск (без пагинации)

`size = min(limit, 100)`, `from = 0`, без страничного обхода. Это
согласуется с поведением остальных провайдеров Papeer (одна страница на
поиск) и с `limit` интерфейса. Пагинация остаётся в Python-референсе
(харвестеру она была нужна, Papeer — нет).

### 3. Решение по Referer: без капчи

Проблема: `DownloadFile` шлёт Referer только как `https://<host>/` и только
на 2-3 попытках; CyberLeninka требует Referer на страницу статьи
(URL = PDF URL без суффикса `/pdf`), иначе капча.

Решение: добавить в `httpclient` метод
`DownloadFileWithReferer(ctx, rawURL, referer string)` — общая приватная
реализация текущего `DownloadFile`, где referer подставляется на **все**
попытки (не только 2-3). Существующий `DownloadFile` остаётся обёрткой с
пустым referer (поведение не меняется). В `FetchPDF` в начале вычисляем
referer по хосту: для `cyberleninka.ru` — URL с отрезанным `/pdf`
(страница статьи), для остальных — пусто; все внутренние вызовы
`client.DownloadFile` заменяются на замыкание
`download(u) = client.DownloadFileWithReferer(ctx, u, referer)` (3 места:
шаги 1, 3a, 3b + повтор в Akamai-цикле).

Альтернативы:
- `SetHostHeader("cyberleninka.ru", "Referer", ...)` — статичный заголовок,
  а Referer динамический (своя страница у каждой статьи) — не подходит.
- Referer только на 2-3 попытках через существующий механизм (`https://<host>/`) —
  не гарантирует прохода (референс требует страницу статьи) и на первой
  (основной) попытке капча неизбежна.
- Обработка исключительно в fetcher через кастомный заголовок-маркер —
  нарушает чистоту httpclient. Принятый вариант проще и переиспользуем.

### 4. Источник `cyberleninka` — статический резолвер

`Resolve` без сетевых вызовов: если `info.PdfURL` содержит
`cyberleninka.ru` — вернуть как есть, иначе `Reason: "not a cyberleninka paper"`.
По сути это аналог `search_report`, но с фильтром по хосту. Место в цепочке —
сразу после `search_report` (`search_report, cyberleninka, arxiv, s2_doi, ...`):
для RU-статей это единственный рабочий источник, а его резолв ничего не стоит
сетевым вызовом. Для EN-статей с пустым PdfURL он сразу отказывается и
передаёт ход дальше.

### 5. Rate-limit и проба доступности

- `client.SetHostRateLimit("cyberleninka.ru", 0.5)` рядом с прочими
  per-host настройками в `makeHTTPClient` (`app.go` ~910–915) — ~1 запрос
  в 2 c, как в референсе (1.2–2 c).
- Проба в `CheckSearchProviders`: эндпоинт поиска — только POST, GET-пробы
  (`DoJSON`/`DoText`) к нему неприменимы, поэтому проба — `DoText` на
  `https://cyberleninka.ru` (проверка достижимости хоста; API-слой отдельно
  проверится первым реальным поиском).

### 6. Тесты

- Провайдер: `httptest` — как в `providers_http_test.go`; проверить
  маппинг, снятие `<b>`-тегов, yearMin-фильтр, cap 100, пустой DOI,
  POST-форму запроса (проверяем `method` и тело в обработчике).
- Источник: `sources_http_test.go` — резолв cyberleninka-URL и отказ для
  чужих/пустых.
- `DownloadFileWithReferer`: проверка, что referer попадает в заголовки
  запроса (существующий `client_test.go`).
- Частичная проверка `FetchPDF` + Referer — через unit-тест httpclient
  (полный e2e с капчой не гоняем).

### 7. Языковой скоуп оси `lang_scope` и язык провайдера

Требование пользователя: дефолт поиска по оси — только англоязычные
источники; флаг на оси — только русскоязычные. Отсюда колонка **не boolean,
а тип языка**: `axes.lang_scope TEXT NOT NULL DEFAULT 'en'` (значения `en` /
`ru`).

- **Миграция**: `ALTER TABLE axes ADD COLUMN lang_scope TEXT NOT NULL DEFAULT
  'en'` в `migrate()` по существующему идемпотентному паттерну
  (`sqlite.go:71`). Старые строки получают `'en'` автоматически — поведение
  текущих (англоязычных) осей не меняется. `db.Axis.LangScope string` (json
  `lang_scope`), включается в SELECT/INSERT/UPDATE в `db/axis.go`.
- **Интерфейс провайдера**: в `search.Provider` добавляем `Language() string`
  (`"en"`/`"ru"`). Это расширяемо для будущих источников: новый RU-источник —
  просто ещё один провайдер с `Language() = "ru"`, без центрального реестра и
  без правок движка.
- **Фильтр в движке**: скоуп читается прямо из `input.Axis.LangScope`
  (нормализация: пустое → `"en"`), отдельное поле в `SearchAxisInput` **не
  заводим**. `Axis` уже передаётся в `SearchAxisInput` целиком (`app.go:690`,
  `Axis: *axis`), поэтому lang_scope попадает в движок автоматически — в
  `app.go` править нечего. `SearchAxis` пробрасывает скоуп в
  `searchQueryParallel`, который отбирает `p.Language() == scope`.
- **Моки в тестах**: `mockProvider` в `engine_test.go` дополняется полем и
  методом `Language()`; провайдерам в `providers_test.go` добавляются
  соответствующие методы (`"en"` всем четырём, `"ru"` — cyberleninka).
- **UI**: в форме оси — контрол выбора языка источников (radio: Англ./Рус.)
  с биндингом `axis.lang_scope`; i18n-ключи `axes.langScope` + опции.

Альтернатива (отклонена): булева колонка `ru_only` + реестр RU-имён в
`app.go`. Причина: не выражает дефолт «EN-only» (булев 0 = «все источники»),
а реестр вне провайдеров придётся держать в двух местах при добавлении
новых RU-источников.

## Risks / Trade-offs

- [Эндпоинт недокументированный] → единственная точка правки — DTO в
  `cyberleninka.go`; формат стабилен (используется сайтом).
- [Смена дефолта поиска: оси, созданные до фичи, станут EN-only] → именно это
  и есть требуемое поведение; миграция проставляет `'en'` старым строкам,
  для RU-поиска пользователь явно включает `ru` на оси.
- [Ретраи без подтверждения со стороны API] → бэкофф 3/8/20 c из боевого
  референса; circuit breaker движка — второй рубеж.
- [Капча при неверном Referer остаётся невидимой для тестов] →
  валидация `%PDF-` + размер (`validator.go`) отсекает HTML-заглушки при
  реальном использовании; ручная проверка из DoD обязательна.
- [`DownloadFileWithReferer` расширяет публичный API httpclient] →
  старый метод остаётся нетронутым (обёртка), регрессий не несёт.
- [UA-ротация скачивания не подстраивается под язык] → Accept-Language в
  `DownloadFile` уже содержит `ru;q=0.8`, UA браузерные — достаточно.

## Migration Plan

- Безопасное развёртывание: изменения аддитивные (новые файлы + строки
  регистрации); старые провайдеры/источники не трогаются.
- Откат: удалить строки регистрации; файлы провайдера/источника можно
  оставить неиспользуемыми.
- Ручная проверка из DoD: поиск «рекомендательная система абитуриент» →
  статьи; approved-статья c CyberLeninka → валидный PDF.
